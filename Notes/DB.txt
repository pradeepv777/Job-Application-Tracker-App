────────────────────────────────────────────────────────────────────────────────
  RELATIONSHIPS DETAIL
────────────────────────────────────────────────────────────────────────────────

  users → applications
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Type        : One-to-Many                                              │
  │  FK          : applications.user_id → users.id                         │
  │  SQLAlchemy  : User.applications  (back_populates="owner")             │
  │               Application.owner   (back_populates="applications")      │
  │  On Delete   : No explicit DB cascade — handled at app layer           │
  │  Meaning     : Each user owns their own set of job applications.        │
  │                A user can have zero or more applications.               │
  │                An application always belongs to exactly one user.       │
  └─────────────────────────────────────────────────────────────────────────┘

  applications → interviews
  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Type        : One-to-Many                                              │
  │  FK          : interviews.application_id → applications.id             │
  │  SQLAlchemy  : Application.interviews (back_populates="application",   │
  │                                        cascade="all, delete")          │
  │               Interview.application   (back_populates="interviews")    │
  │  On Delete   : CASCADE — deleting an application deletes all its       │
  │                interviews automatically                                 │
  │  Meaning     : Each application can have multiple interview rounds.     │
  │                An interview always belongs to exactly one application.  │
  └─────────────────────────────────────────────────────────────────────────┘


────────────────────────────────────────────────────────────────────────────────
  CASCADE BEHAVIOUR
────────────────────────────────────────────────────────────────────────────────

  DELETE user
      └── does NOT auto-delete applications (app layer deletes them first)

  DELETE application
      └── auto-deletes all linked interviews  ← cascade="all, delete"

  This means you can never have a dangling interview with no application.

────────────────────────────────────────────────────────────────────────────────
  OWNERSHIP & DATA ISOLATION
────────────────────────────────────────────────────────────────────────────────

  Every query in the API filters by the authenticated user's id:

    applications  →  WHERE user_id = current_user.id
    interviews    →  JOIN applications WHERE user_id = current_user.id

  Users can only see and modify their own data. There is no shared or
  cross-user data access in any endpoint.
